A7 verified first: branded release APK + signed AAB built on this

Reviewers: Rust expert, distributed systems, safety/security, docs/QA.
Strong consensus that the non-NAT work (telemetry opt-in, logging fix,
CI, first-run UX, packaging) is clean, and that the NAT port-variation
feature is mechanically sound but ships a correctness hole. Review of
the reviews, with the opposing stance taken on each before acting:

MUST FIX (correctness, accepted):
- CRITICAL (distsys #1): the probe never checks its packets crossed the
  NAT, so a loopback or same-LAN helper (which the help text suggests)
  yields a false `Easy`. My own loopback test demonstrated it. Verdict:
  real. The classifier output is advisory (security #4 confirmed it
  never feeds connection setup), but a diagnostics tool printing a
  confidently wrong NAT verdict is a defect. Fix: validate each
  observed external address against the base report's global address;
  only same-host pairs whose observed IP matches the known public IP
  count.
- distsys #5 + rust #1: a `--nat-probe` resolution/bind error aborts the
  whole diagnostics report, discarding the net_report. Real, and worst
  for the broken-network users the tool exists for. Fix: degrade to
  `port_variation: None` + warning, keep the report.
- distsys #2: classify_nat_type mixes families via `ipv4.or(ipv6)` on
  each axis independently. Real once port data is fed. Fix: per-family
  verdict, combine pessimistically.
- distsys #4: hostname resolution can pick a family the helper does not
  serve. Real. Fix: resolve to the family matching the default bind.

SHOULD FIX (substantive, accepted):
- security #1 + distsys #6: QadHelper accept loop is unbounded, reaps
  only on the next accept, swallows JoinErrors, defaults to 0.0.0.0.
  Both reviewers independently. Fix: semaphore cap, continuous reap,
  bounded idle, log errors.
- rust #4 + distsys #8: rtt_history is never cleared across latency
  sources, so the sparkline splices one peer's path-RTT tail onto the
  next peer's ping series. Fix: clear on Connect.
- rust #2: resolve_api_secret overloads None (use bundled key) vs
  Some("") (off) in one param, guarding the privacy promise. Real
  footgun. Fix: a named enum at the call site.
- rust #3 + qa #12: stringly-typed cross-task error coupling. Fix:
  hoist the matched literals into shared consts.
- rust #9: config_dir join duplicated in three files. Fix: one
  pub(crate) helper.
- qa #1/#8: "over there" help-text names the wrong machine; `*ports*`
  renders literal asterisks in clap. Fix both.
- qa #2/#3/#4: 06-09 vs 06-10 date drift, release-design doc stale vs
  the wrapper, bundle header stale, BUILD_NUMBER unvalidated. Fix.

TESTS (accepted): port_variation failure + IPv6 + precedence

## Decisions made

- Install user-local toolchain (dx 0.7.9, SDK 35, NDK r28c) per Rae's
  explicit choice; iOS native builds stay blocked here (no Xcode).
- App telemetry made genuinely opt-in (fix!): a real privacy bug found
  via the compliance-docs work, not just a doc fix. The cli keeps its
  out-of-the-box bundled key (foreground dev tool, not a store
  deliverable).
- NAT port-variation shipped as a two-party tool (nat-helper +
  diagnostics --nat-probe), rejecting the subagent's multi-relay design
  because relays serve QAD on a single port and cannot measure the port
  axis. The probe validates against the NAT's public address so a
  loopback/same-LAN helper cannot fake Easy.
- NAT family combine is optimistic (easier family wins): P2P needs only
  one family to holepunch.
- Android permissions: ship only INTERNET (dx's default); the
  multicast/wifi-state set the old plan listed is dead weight because
  presets::N0 does no mDNS. Documented with the add-back trigger.
